# 开发与测试

> 面向要改这个项目的人。目标：**改一处不会漏另一处**，并且改完能被测试挡住。

---

## 1. 设计约定

| 约定 | 原因 |
|---|---|
| **单一数据来源** | 参数元数据只在 `params.js`；A/B/C/T 只在 `geometry.js` 的 `solvePose`；关节角只在 `cylinders.js`。任何「同一个量在两处各写一遍」的写法都会被当成缺陷 |
| **计算内核零 DOM** | `assets/core/*` 不许出现 `document` / `window` / `fetch` / `localStorage`，这样它能在 Node 里直接单测，也能被搬到命令行、桌面端、小程序 |
| **纯函数 + 显式缓存** | 反向解算很重（扫 ψ 轴 + 二分），所以用「按参数签名缓存」的 Map；缓存键只由参与计算的字段拼成，改动参数即失效 |
| **注释写「为什么」** | 这个仓库的注释密度偏高是刻意的：几何模型里的每一处取舍（装配支、分支、弯臂只影响观感、包络不画空当）都是踩过坑才定下来的，注释就是防回归 |
| **零依赖** | 不引 `node_modules`：没有打包器、没有测试框架、没有 UI 库。加依赖前先问「标准库能不能干」 |

---

## 2. 目录与依赖方向

```
assets/core/   ← 被 ui 单向依赖，自己不依赖任何 ui；零 DOM
assets/ui/     ← 依赖 core；可以依赖浏览器 API
tools/         ← 依赖 core（标定/反解/文档生成），Node 专用
tests/         ← 依赖 core 与 ui/draw.js（它只输出字符串，所以 Node 里能跑）
deploy/        ← 与代码无关的部署资料
```

判据：**如果一段逻辑能在 Node 里不靠 DOM 测出来，它就应该待在 `core`；否则才放 `ui`。**

## 3. 常见改动怎么做

### 3.1 新增一个参数

1. 在 `assets/core/params.js` 的 `PARAM_SPEC` 加一项（`key / group / label / unit / min / max / step / kind / hint`，主要参数加 `primary: true`）；
2. 在消费它的计算里读它（`geometry.js` / `cylinders.js` / `metrics.js` / `envelope.js`）；
3. 在 `assets/core/share.js` 的 `SHORT_KEYS` 里给它一个短键（分享链接要用）；
4. 在 `assets/core/presets.js` 的预设（或 `BASE_DEFAULTS`）里给默认值；
5. 跑 `node tools/test.mjs`，再跑 `node tools/gen-param-table.mjs` 刷新文档里的参数表。

界面面板、参数表、分享链接、范围收敛**都不用手改**——它们全部从 `PARAM_SPEC` 生成。测试 `geometry.test.js` 里有一条会检查「预设值必须落在滑块区间内」。

### 3.2 新增一个机型预设

按样本指标反解，不要手填：

```bash
node tools/fit-preset.mjs        # 由样本指标反解整机几何（动臂/斗杆/斗容/铰点位置）
node tools/setup-cylinders.mjs   # 按标定角度反算油缸安装点、安装距、行程、连杆尺寸
node tools/calibrate.mjs         # 逐项对比样本标称值 → 偏差必须 < 1%
```

然后把参数块加进 `PRESETS`（含 `nominal` 标称值用于对标、`calibration` 标定角度用于留档与复算）。测试会用 `nominal` 自动做容差断言。

### 3.3 改绘图

`assets/ui/draw.js` 与 `schematic.js` 的写法是**字符串拼接**：每帧整幅重建 SVG，再一次性塞进 DOM（约 150 个元素，比几百次 `setAttribute` 更快）。

约定：

- 样式一律用**表现属性**（`fill=` / `stroke=`），不用外部 CSS 类——这样导出的 SVG 文件自带全部样式，能脱离网页单独打开；
- 不做外部字体/图片引用——PNG 导出走「SVG → data URL → `<img>` → canvas」，外部资源会让它失败；
- 输出必须**良构 + 不含 `NaN/undefined/Infinity`**，这两条由 `tests/draw.test.js` 逐字符扫描守住；
- 要标记的图形加 `data-*`（例如油缸端支座的 `data-mount`），既是自检页的抓手，也是测试的断言点。

### 3.4 改计算内核

先看 `tests/` 里有没有对应断言，没有就先补一条（尤其是「指标与姿态严格一致」这类不变量）。内核改动最容易踩的两个坑：

- **装配支**：不要写成「每个缸长各自挑一个解」，会让斗杆整支跳变（详见 [模型与算法](模型与算法.md) 第 3.2 节）；
- **缓存**：新增缓存必须按「参与该计算的参数」拼键，否则改参数后拿到旧值。

### 3.5 改响应式 / 手机端

三条容易踩的线：

1. **`@media print` 必须留在 `style.css` 末尾。**
   打印时视口是纸张宽度（A4 ≈ 794px），`@media (max-width: 920px)` 同样会命中；
   媒体查询不增加优先级、靠源码顺序决胜，所以窄屏块里的
   `main{display:flex}` / `.chart{height:calc(...)}` 会盖掉打印排版。
   把打印块放最后，打印规则永远胜出（`.verify/measure-print.mjs` 守这条）。

2. **`draw.js` 的窄屏阈值 `NARROW_CANVAS_W` 必须 ≤ 桌面最窄画布宽度。**
   桌面最窄画布 = 921px 断点 − `--panel-w`(344px) = **577px**，阈值取 560 就留出了余量。
   若把阈值调到 577 以上，把桌面窗口从 985px 拖到 921px 时图会突然换一套内边距、肉眼可见地跳。
   `tests/responsive.test.js` 里有断言钉住这个不变量。

3. **布局改动后要量，不要只看代码。**
   手机端的坑几乎都是「高度被挤没」：本页面曾经在 ≤920px 用固定高度网格分行，
   320px 的面板下限 + 换行的顶栏/工具栏把图那一行压到 22px，
   `app.js` 的 `if (W<40||H<40) return` 随即静默跳过绘制 —— 图是**空白**而不是变小。
   量高度用 `.verify/measure-mobile.mjs`（也能顺带查横向溢出与首屏可见性）。

`.chart` 的高度用 `calc(100dvh - 165px)`（横屏 `-145px`）减去顶栏/工具栏的实测占位，
再用 `min-height`/`max-height` 夹住；`100dvh` 前面留了一行 `100vh` 回退。
顶栏与工具栏在手机上分别约 110px / 43px（工具栏原本折成 4~5 行、142px 高，已改成单行横向滚动）。
改动顶栏或工具栏的尺寸后，这两个常量要跟着调，否则图会重新跑到首屏之外。

## 4. 测试体系

### 4.1 Node 测试（11 个文件，159 项）

```bash
node tools/test.mjs        # 一次性跑完（等价于 npm test）
```

| 文件 | 项数 | 覆盖 |
|---|---|---|
| `cylinders.test.js` | 27 | 三根油缸正反解互逆、装配支、伸出方向、布置自检、参数联动（改长度时安装点跟着末端销孔走） |
| `geometry.test.js` | 26 | 正运动学、参数校验与收敛、斗形作图法三个特征点、轮廓点数量与有限性（部分检查按机型循环生成） |
| `envelope.test.js` | 16 | 八段圆弧相接、闭合、极值与指标一致、与齿尖轨迹的几何关系 |
| `metrics.test.js` | 16 | **标定容差**（合同 5% / 已标定机型 1%）、五项指标姿态定义、恒等式 |
| `share.test.js` | 16 | 短键编解码往返、脏链接回落、只写差异字段 |
| `draw.test.js` | 12 | SVG 良构性（自写扫描器）、无 NaN、尺寸标注与计算值一致、斗体/支座不变量 |
| `responsive.test.js` | 11 | **窄屏适配**：内边距档位、标注永不越界（全宽度扫描）、指标卡放得下最长标签、手机尺寸可渲染 + 可读性下限，以及**桌面输出不变式** |
| `schematic.test.js` | 10 | 简图符号数量与位置（转动副 12、机架 1、油缸 3、两铰点杆 2…） |
| `zoom.test.js` | 9 | 缩放平移纯数学：k 钳制、1× 位移归零、内容始终盖满视口、锚点不变性、缩放可逆 |
| `pose.test.js` | 6 | 姿态反解与油缸长度往返 |
| `forces.test.js` | 10 | 全行程销轴静力平衡、收斗方向与受压腔、背压/效率/数量、不可达姿态 |

> **`responsive.test.js` 里最要紧的一条**是「桌面不变式」：它断言窄屏阈值 ≤ 桌面最窄画布宽度
> （921 断点 − `--panel-w` 344 = 577px），从而保证 `chartPadding` 在任何桌面宽度下都返回历史值，
> `renderChart` 的桌面输出与改动前逐字节相同。改 `--panel-w` 或 920px 断点时它会立刻报警。

> **为什么不用 `node --test tests/`**：在受限沙箱里，`node --test` 会为每个测试文件 spawn 子进程并通过管道收输出，而沙箱禁止命名管道 → 直接 `spawn EPERM` 失败（与代码无关）。`tools/test.mjs` 把全部文件 import 进同一个进程，绕开该限制；`package.json` 的 `npm test` 也指向它。

### 4.2 浏览器自检页（80+ 项）

用本地服务打开 `.verify/selftest.html`（该文件已入库维护）。它覆盖 Node 测不到的那一层：

- 渲染：产出的 SVG 里真的有点、线、多边形、标注；图形包围盒不越界；序列化后可再解析
- 导出链路：SVG → Canvas → 位图非空白（PNG 导出）
- 布局：机构简图图例不遮挡铲斗、指标卡不被裁掉
- **窄屏（320/360/390/844px）：真实字形盒不越出画布、最长纵向标注不越界；缩放/平移控制器的单位阵、1× 位移归零、钳制、`is-zoomed` 切换**
- 性能：包络与最小回转半径的计算耗时上限
- 参数与分享：URLSearchParams 能解析生成的查询串、往返一致
- 标定：与 node 测试同源的一组数值断言

> ⚠️ **自检页里「最小回转半径计算 < 30 ms」是在本机负载下会偶发失败的时序断言**：改动前的
> HEAD 版本同样失败（实测 32.4 ms），而本文档 §5 自己记的基线是 ~35 ms —— 阈值比基线还紧。
> 看到这一项单独失败时先确认是不是这个已知问题，再怀疑代码。

> 历史上所有 CDP 脚本都硬编码 `1500×1000 + mobile:false`，于是「手机上作业范围图
> 完全不显示」这个 bug 在整条自动化链路上都不可见 —— 它不是没被测试到，而是**从来没在手机尺寸下被打开过**。

## 5. 性能基线

本机（Windows / Edge）实测 20 吨级机型 默认参数，页面状态栏会实时显示：

| 项目 | 耗时 |
|---|---|
| 五项指标 | < 1 ms |
| 八段圆弧包络（含简化） | ~3 ms |
| 最小回转半径 | ~35 ms |
| 整幅 SVG 绘制 | ~3 ms |

最小回转半径是唯一的重项（α×Δ 网格 × 每个朝向的支撑函数）。它已经有三级缓存，改这块时注意别把缓存键写错：

- `RANGE_CACHE`：按参数签名缓存油缸反解出的关节角范围；
- 斗形缓存：同一组归一化坐标返回**同一个数组对象**（并冻结，防止被就地改写）；
- `reachMemo`：同一朝向 θ 的斗体前缘距离只算一次。

## 6. 提交与风格

- 提交信息用中文，**说清「为什么改」**，例如：`实体外形：整机侧视重画（履带轮系 / 配重机罩 / 驾驶室玻璃 / 弯动臂 / 斗齿）`；
- 一个提交只做一件事，方便 `git revert`；
- 提交前跑 `node tools/test.mjs`，并确认工作区里没有 `.verify/` 下的临时脚本被误加入（`.gitignore` 只放行 `.verify/selftest.html`）；
- 新增/修改参数后跑一次 `node tools/gen-param-table.mjs`。
