## 2. 日常更新流程

```powershell
# ① 打包（会做三项体检：文件齐全、UTF-8 无 BOM、无本地调试地址残留）
#    本机只有 Windows PowerShell 5.1（没有 pwsh）且脚本未签名，所以用 powershell.exe + Bypass
powershell.exe -NoProfile -ExecutionPolicy Bypass -File deploy\package.ps1
#    → dist/excavator.tar.gz

# ② 上传到远端的新文件名（文件名带版本/commit，避开 upload 的「已存在是否覆盖」交互询问）
workbench upload dist\excavator.tar.gz /root/excavator-<commit>.tar.gz --instance-id <实例ID>

# ③ 服务器端按目录发布流程准备、验证、备份、原子交换
#    详见 deploy/README.md 第 1 节；长脚本先上传，再执行
workbench exec --instance-id <实例ID> --timeout 120 -c 'python3 /root/<发布脚本>.py'

# ④ 外部验证：逐文件比对 sha256（这一步不做，「部署成功」就只是一句话）
$env:SITE = 'http://<域名或 IP>'
node tools/verify-deploy.mjs
#    不带 SITE 时默认校验本地服务 http://127.0.0.1:8080（改版前自检用）
```

`tools/verify-deploy.mjs` 会逐文件拉取线上内容与本地比对（带穿透串绕开缓存）、检查首页 200 与 UTF-8、检查页面原样资源引用、抽查已有特性关键字。当前版本的结果应为 **17/17 文件一致、8 个页面引用通过**。

本次发布先在新目录解包和校验，再备份旧站点，用 `renameat2(..., RENAME_EXCHANGE)` 交换目录。站点继续使用原 nginx 配置；静态文件更新无需重载服务。只更新文档、示例图或开发工具时，部署包的内容不会变化。

## 3. 回滚

优先使用发布目录中保留的上一版，或从 `/root/site-backup-<版本>` / 上一版压缩包恢复到新的临时目录。确认内容和权限后，按相同的原子交换流程恢复完整站点。

回滚后，用与目标旧版本对应的本地 checkout 执行 `node tools/verify-deploy.mjs`；否则本地仍为新版，内容比对会按预期报差异。脚本默认生成新的缓存穿透串，也可在 PowerShell 中设置 `$env:STAMP = '<新校验戳>'`。

## 4. 注意事项

| 项 | 说明 |
|---|---|
| **本机出网要代理** | 本机直连 GitHub / 部分外网不通，系统代理在 `127.0.0.1:7897`。`workbench` 走的是阿里云通道，不受影响；`git` 走 GitHub 时需要 `http.proxy` + `http.sslBackend=openssl`（schannel 在受限沙箱里拿不到凭证） |
| **沙箱与 workbench** | `workbench` CLI 通过本机命名管道与守护进程通信，受限沙箱会拒绝（`Access is denied`，退出码 6）。执行上传/部署命令时需要为该命令放宽权限 |
| **缓存** | 线上静态资源是 **5 分钟**缓存（2026-10-05 已核对），文件名不带内容指纹。缩短服务器缓存不会清除浏览器中已有的长缓存，因此入口与模块引用同时使用 `?v=<发版戳>`。九段修复将 `index.html` 的 `app.js` 引用及 `app.js` 的 `envelope.js` 引用更新为 `20261006b`，未修改模块保留原戳；此版本尚未部署。未来发布后需检查页面原样引用及实际模块请求，详见 `deploy/nginx-excavator.conf` |
| **配置漂移** | 线上 `/etc/nginx/sites-available/excavator` 与仓库里的 `deploy/nginx-excavator.conf` **不是同一份**（线上是 80 + 443 自签证书两个 server 块、入口页没有 no-cache 块）。**不要**拿仓库文件直接覆盖线上配置；改之前先 `cat` 线上文件、先备份（`cp -a $f $f.bak-$(date +%Y%m%d-%H%M%S)`），改完 `nginx -t` 通过再 `systemctl reload nginx` |
| **HTTPS** | 443 已监听但是**自签证书**，浏览器提示不受信；要正式用需域名 + 可信证书（Let's Encrypt / 阿里云证书） |
| **域名上线** | 域名、证书和备案等条件按实际服务场景及云厂商当前要求另行核对 |
| **账号密钥** | 阿里云 AK 只从 `~/.workbench/config.json` 读取，不落盘、不打印；`deploy/aliyun-sg.mjs` 只用于查/放行安全组端口 |
| **回滚点** | 每次发布前保存上一版整目录；本次备份为 `/root/site-backup-2ecf455-20261005145811` |
