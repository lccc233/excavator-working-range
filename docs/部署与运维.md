## 1. 线上环境

| 项 | 值 |
|---|---|
| 线上地址 | **http://<域名或 IP>/** |
| 实例 | 阿里云 ECS `<实例ID>`（cn-hangzhou，Ubuntu），弹性公网 IP `<域名或 IP>` |
| Web 服务器 | nginx，站点目录 `/var/www/excavator`（属主 www-data） |
| 站点配置 | `/etc/nginx/sites-available/excavator` → `sites-enabled/excavator` |
| 传输方式 | 阿里云 `workbench` CLI（免公网 IP 的 ECS 通道）：`upload` 传包、`exec` 执行远端命令 |

**交付物形态**：纯静态站点，**没有构建步骤、没有运行时依赖、没有后端**。上线内容只有 `index.html` + `assets/**`（15 个文件，约 213 KB）；`tests/ tools/ deploy/ docs/ .verify/` 一律不上线。所有计算在浏览器里完成，参数通过 URL 分享，服务端不存任何数据。

## 2. 日常更新流程

```bash
# ① 打包（会做三项体检：文件齐全、UTF-8 无 BOM、无本地调试地址残留）
#    本机只有 Windows PowerShell 5.1（没有 pwsh）且脚本未签名，所以用 powershell.exe + Bypass
powershell.exe -NoProfile -ExecutionPolicy Bypass -File deploy\package.ps1
#    → dist/excavator.tar.gz

# ② 上传到远端的新文件名（文件名带版本/commit，避开 upload 的「已存在是否覆盖」交互询问）
workbench upload dist\excavator.tar.gz /root/excavator-<commit>.tar.gz --instance-id <实例ID>

# ③ 备份 + 解包替换 + reload（整目录替换；回滚就是把这步的备份目录拷回去）
#    ⚠️ -c 后面整段用单引号包住：远端命令里写双引号会被 PowerShell 吃掉（实测 curl -w 因此 exit 2）
workbench exec -i <实例ID> --timeout 120 -c 'set -e; \
  ts=$(date +%Y%m%d-%H%M%S); cp -a /var/www/excavator /root/site-backup-$ts; \
  rm -rf /var/www/excavator/*; tar -xzf /root/excavator-<commit>.tar.gz -C /var/www/excavator; \
  chown -R www-data:www-data /var/www/excavator; nginx -t && systemctl reload nginx; \
  echo backup=/root/site-backup-$ts; \
  curl -s -o /dev/null -w localhost_index=%{http_code} http://127.0.0.1/'

# ④ 外部验证：逐文件比对 sha256（这一步不做，「部署成功」就只是一句话）
SITE=http://<域名或 IP> node tools/verify-deploy.mjs
#    不带 SITE 时默认校验本地服务 http://127.0.0.1:8080（改版前自检用）
```

`tools/verify-deploy.mjs` 会：逐文件拉取线上内容与本地比对（带穿透串绕开 7 天缓存）、检查首页 200 与 charset、抽查关键特性关键字。**15/15 一致才算通过**。

## 3. 回滚

站点目录是整目录替换，所以回滚有两种：

```bash
# 方式一：用部署时自动建的备份（推荐，最快）
workbench exec -i <实例ID> -c 'set -e; cp -a /root/site-backup-<时间戳>/. /var/www/excavator/; nginx -t && systemctl reload nginx; ls /var/www/excavator'

# 方式二：重新解包上一个版本的 tar.gz
workbench exec -i <实例ID> -c 'set -e; rm -rf /var/www/excavator/*; tar -xzf /root/excavator-<旧commit>.tar.gz -C /var/www/excavator; chown -R www-data:www-data /var/www/excavator; nginx -t && systemctl reload nginx'
```

回滚后同样用 `node tools/verify-deploy.mjs` 验证（记得 `STAMP` 用新值穿透缓存）。

## 4. 注意事项

| 项 | 说明 |
|---|---|
| **本机出网要代理** | 本机直连 GitHub / 部分外网不通，系统代理在 `127.0.0.1:7897`。`workbench` 走的是阿里云通道，不受影响；`git` 走 GitHub 时需要 `http.proxy` + `http.sslBackend=openssl`（schannel 在受限沙箱里拿不到凭证） |
| **沙箱与 workbench** | `workbench` CLI 通过本机命名管道与守护进程通信，受限沙箱会拒绝（`Access is denied`，退出码 6）。执行上传/部署命令时需要为该命令放宽权限 |
| **缓存** | 线上静态资源是 **7 天**缓存且文件名不带内容指纹 —— 发新版后老访客可能仍拿旧 JS，需要强刷（Ctrl+F5）。要根治得给文件名加指纹或把缓存降到分钟级 |
| **配置漂移** | 线上 `/etc/nginx/sites-available/excavator` 与仓库里的 `deploy/nginx-excavator.conf` **不是同一份**（线上多了 443 + 自签证书的 server 块、缓存 7 天、没有 index.html 的 no-cache 块）。**不要**拿仓库文件直接覆盖线上配置，改之前先 `cat` 线上文件 |
| **HTTPS** | 443 已监听但是**自签证书**，浏览器提示不受信；要正式用需域名 + 可信证书（Let's Encrypt / 阿里云证书） |
| **域名与备案** | 用域名对外服务必须 ICP 备案（10–20 工作日）；`http://IP` 直连不需要，适合测试 |
| **账号密钥** | 阿里云 AK 只从 `~/.workbench/config.json` 读取，不落盘、不打印；`deploy/aliyun-sg.mjs` 只用于查/放行安全组端口 |
| **回滚点** | 每次部署都会在 `/root/site-backup-<时间戳>` 留一份上一版整目录 |

## 5. 首次部署做过什么

完整记录见 [deploy/README.md](../deploy/README.md)：装 nginx 并设为开机自启 → 上传解包到 `/var/www/excavator` → 写站点配置并禁用默认站点 → 用 `deploy/aliyun-sg.mjs` 通过 ECS OpenAPI 放行 80 → 外部逐文件 sha256 校验。
